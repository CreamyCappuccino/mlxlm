## 概要

### 現在の問題点
- `search.py` が 932 行に肥大化（モノリシック構造）
- 保守性が低下、新機能追加が困難
- 表示・フィルター・インタラクティブUIの処理が混在
- Phase 1-5 の拡張に向けてモジュール化が必須

### 解決策
`search.py` を 4 つの集中したモジュールに分割：
- **search.py** (630行) - メインエントリー・オーケストレーション
- **search_display.py** (280行) - フォーマット・表示関数
- **search_filters.py** (350行) - フィルター・ソート処理
- **search_interactive.py** (260行) - インタラクティブメニュー処理

### 期待される成果
- v0.3.0 と同じ機能を保持
- モジュール構造により保守性向上
- バグ修正: `--max-size` フィルター論理
- 既存テスト全て PASS (49/49)

## リファクタリング中に修正する既知の問題

### 問題: Size フィルター論理
**現在の動作（バグ）**:
```python
# apply_filters() 内, line ~450
if state.apply_size_filter:
    if state.min_size and model_params < state.min_size:
        continue
    if state.max_size and model_params > state.max_size:  # バグ: >= にすべき？
        continue
```

**修正**:
```python
if state.apply_size_filter:
    if state.min_size and model_params < state.min_size:
        continue
    if state.max_size and model_params > state.max_size:  # 正確: max より大きい場合は除外
        continue
```

**テストケース**:
```bash
mlxlm search llama --max-size 13
# 7B, 13B は含む、30B は除外すべき
# search_filters.py:handle_size_filter() で検証
```

## ロールバック計画

リファクタリング中に問題が発生した場合：

1. **単一関数の破損**: 元のコードからその関数だけ復元
2. **インポートの問題**: 循環依存をチェック、再構成
3. **テスト失敗**: マイグレーションステップに遡って修正
4. **完全ロールバック**: `git reset --hard HEAD~N` または `dev` ブランチに切り替え
