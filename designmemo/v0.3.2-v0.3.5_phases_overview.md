## 各フェーズ概要

### Phase 1: Query optional 化 + デフォルト 10 件表示 (v0.3.2)

**問題**:
- `mlxlm search` のみでエントリーできない
- `mlxlm search --help-detail` が動かない（query 必須のため）
- デフォルト 7 件表示は数百種モデル時に不便

**実装内容**:
```bash
mlxlm search            # → 全モデルランキング（10件）
mlxlm search llama      # → llama検索（10件）
mlxlm search --help-detail  # → ヘルプ表示（動作）
```

**修正ファイル**:
- `cli_flags.py`: query を `nargs='?'` に（オプショナル化）
- `search.py`: query=None 時の分岐処理・デフォルト値変更

**行数影響**: +20行

---

### Phase 2-3: メニューコマンド統一 + スラッシュコマンド (v0.3.3)

**問題**:
- メニューが 1-7, 8, 9, 0 に縛られている
- キーボード操作が制限的（n/N, f/F などが使えない）
- スラッシュコマンドで素早い操作ができない

**実装内容**:

**Phase 2 - メニューコマンド統一**:
```
従来: 1-7, 8 (次), 9 (フィルター), 0 (終了)
改善: 1-10+, n/N (次), f/F (フィルター), s/S (新規検索), d/D (表示件数), 0 (終了)
```

**Phase 3 - スラッシュコマンド**:
```bash
/search <keyword>    # 新規検索
/display <数値>      # 表示件数変更
/display reset       # デフォルト 10 件に戻す
/exit                # 終了
```

**修正ファイル**:
- `search_interactive.py`: choice 処理の拡張、slash command parser 追加
- `search_display.py`: 動的メニュー表示

**行数影響**: +150行

---

### Phase 4: 設定ファイル保存 (v0.3.4)

**問題**:
- フィルター設定がセッション内でリセットされる
- ユーザーが設定した表示件数が毎回忘れられる

**実装内容**:
```json
{
  "search": {
    "default_display_count": 10
  }
}
```

**操作例**:
```bash
mlxlm search llama
# /d 20 で表示件数を 20 に変更
# "Save as default? [y/N]" → y
# 次回起動時に 20 件が デフォルトになる
```

**修正ファイル**:
- `core/__init__.py`: "search" セクション追加
- `search.py`: load_user_config(), save_user_config() 呼び出し
- `search_interactive.py`: /d 実行時に保存確認プロンプト

**行数影響**: +40行

---

### Phase 5: パラメータスケールフィルター (v0.3.5)

**問題**:
- モデルサイズ（7B, 13B, 30B など）でフィルターができない
- サイズ情報がモデル名に含まれているが活用できていない

**実装内容**:
```bash
# モデル名から "XB" パターンを抽出
"Llama-2-7B" → 7
"Mistral-7B-v0.1" → 7
"gemma-3-27b-instruct" → 27

# フィルター使用例
mlxlm search llama --param-scale 7 --param-compare eq    # 7B のみ
mlxlm search mistral --param-scale 13 --param-compare lt  # 13B 未満
mlxlm search qwen --param-scale 30 --param-compare gt     # 30B 以上
```

**フィルターメニュー**:
```
6. パラメータスケール (7B, 13B, 30B など)
   比較演算子: eq (=), lt (<), gt (>)
```

**修正ファイル**:
- `cli_flags.py`: `--param-scale`, `--param-compare` フラグ追加
- `search_filters.py`: extract_param_scale(), handle_param_scale_filter() 追加
- `search.py`: search_huggingface() のフィルター処理に追加

**行数影響**: +250行

## 注意点・トラブルシューティング

### 循環インポート
Phase 2-3 で search_interactive.py が search_filters.py を import し、search_filters.py が search_display.py を import している。
循環依存を避けるため、インポートは明確に一方向に保つこと。

### クエリオプション化の影響
Phase 1 で query を optional にしたら、検索エラーハンドリングを確認すること。
例: `mlxlm search` で 0 件の場合、「No models found」メッセージを表示

### パラメータスケール抽出の複雑性
正規表現のパターンマッチが多くのバリエーションを カバーする必要あり。
テストケースを充実させること（7B, 7b, 7-b, 7_b, 7 billion など）
